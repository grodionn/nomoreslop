# Карта UI-анимаций и характер движения

Разделы: 1. Не смешивать независимые оси · 2. Характер: словарь для брифа и поиска · 3. Карта семей: компоненты и изменения · 4. Кривые, spring и inertia · 5. Эталонные механики · 6. Подробности, которые легко спутать · 7. Как агент превращает карту в решение.

Исследовано 29 октября 2026 по первичным документам MDN/W3C, Motion, GSAP, Radix, Carbon и WAI-ARIA APG. Это практическая классификация для выбора и реализации, а не утверждение о конечном числе всех возможных анимаций. Названия разных библиотек могут пересекаться. Загружай относящуюся семью, затем уточняй механизм, состояние и характер. Чужие duration, scale и bezier из учебного примера не становятся обязательными токенами проекта.

## 1. Не смешивать независимые оси

«Smooth», «morph», «scroll» и «dropdown» описывают разные свойства решения. Полезная запись одного эффекта:

`задача → триггер/источник прогресса → состояние A/B → изменяемое свойство → модель времени → характер → оркестрация → прерывание/обратный ход → спокойный вариант`.

| Ось | Разновидности | Пример решения |
| --- | --- | --- |
| Назначение | Отклик; ориентация; раскрытие; связь состояний; ожидание; объяснение данных; брендовый акцент | Открытие меню объясняет связь с trigger; не «анимировать ради современности» |
| Триггер | Hover; focus; press/tap; drag/swipe; key; изменение данных; mount/unmount; viewport; scroll; time; media | Enter в dropdown и mouse hover могут требовать разных веток |
| Источник прогресса | Время; положение/скорость указателя; значение; scroll progress; реальная операция | Progress скачивания не является бесконечным таймером |
| Свойство | Opacity; position; scale; rotation; размер/layout; crop/mask; stroke/path; цвет; фильтр/материал; камера/3D | Одинаковый fade можно запустить и временем, и scroll |
| Модель | Tween; keyframes; spring; inertia; stepped; физическая симуляция | Spring переключателя и линейное вращение спиннера решают разные задачи |
| Характер | Сдержанный; плавный; резкий; упругий; жидкий; механический; невесомый | Sharp не означает пропуск кадров, gooey не является названием easing |
| Оркестрация | Вместе; stagger; последовательность; overlap; follow-through; loop; ping-pong; состояние machine | Задержка группы не должна удерживать главное действие |

Обоснование различать рабочие и выразительные моменты даёт [Carbon motion](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview): продуктовый отклик помогает задаче, выразительное движение получает отдельную роль. Классификация выше — рабочее обобщение для навыка, не цитата из стандарта.

## 2. Характер: словарь для брифа и поиска

| Характер | Наблюдаемое поведение | Что настраивать | Где уместен / типичная ошибка |
| --- | --- | --- | --- |
| Smooth / плавный | Нет заметного скачка скорости/положения, предсказуемое прибытие | Кривую, путь, непрерывность при retarget, отсутствие frame drops | Переход состояния; ошибка — медленный UI с задержкой каждой реакции |
| Snappy / собранный | Быстро понятен результат, короткое видимое установление | Момент отклика, расстояние, затухание/кривая | Частые действия; ошибка — резкий старт с долгим дрожащим хвостом |
| Sharp / crisp / резкий | Чёткие границы, энергичный переход, мало смягчения | Амплитуду, короткую фазу, отсутствие лишнего bounce | Точный инструмент, редакционный акцент; ошибка — мерцание и строб |
| Soft / gentle | Мягкий старт/прибытие и небольшой визуальный вес | Светлоту, расстояние, скорость, форму пути | Ненавязчивое раскрытие; ошибка — блеклый текст и слишком долгая неготовность |
| Spring / elastic | Возврат к целевой позиции с управляемым перерегулированием | Stiffness/damping/mass либо duration/bounce по выбранной модели | Drag-release, thumb, карточка; ошибка — одинаковая пружина для всего |
| Bouncy | Выраженные отскоки/несколько возвращений | Число/амплитуду колебаний, момент готовности | Редкий выразительный момент; ошибка — прыгающая форма с ошибкой |
| Heavy / weighted | Инерционная масса, заметная остановка | Массу, скорость и задержку в пределах сценария | Объёмный объект, крупная панель; ошибка — окно мешает немедленно закрыть его |
| Floating / breathing | Спокойный цикл вокруг опорной позиции | Амплитуду, фазу, период, область и возможность остановки | Изолированный декоративный объект; ошибка — движущаяся hit area кнопки |
| Magnetic / following | Объект/деталь реагирует на расстояние до указателя | Радиус, gain, ограничения, скорость возврата | Выбранное pointer-направление; ошибка — уезжающее действие и второй курсор |
| Gooey / metaball | Слипание и разделение мягких масс | Геометрию/маску/фильтр и параметры смешивания | Связанный с брендом материал; ошибка — слизь вместо читаемой навигации |
| Morph / трансформация формы | Один контур/объект меняет форму в другой | Топологию, соответствие точек, силуэт, конечную узнаваемость | Иконка состояния, предмет; ошибка — самопересечение и потеря исходного знака |
| Liquid / fluid | Вязкость, поток, деформация или рефракция | Поле, displacement, прозрачность, скорость, нагрузку | Ограниченная графическая область; не обещать реальную жидкость по одному blur |
| Mechanical / stepped / stop-motion | Дискретные шаги или намеренная кадровая пластика | Число шагов, позицию скачков, sprite-кадры | Пиксельный/механический визуал; ошибка — stepped progress, скрывающий реальное значение |
| Cinematic | Поставленная смена кадра/фокуса/масштаба | Монтаж, длительность сцены, камеру, иерархию | Контентная история; ошибка — интерфейс ждёт длинную заставку |
| Glitch / rough / jitter | Намеренная нерегулярность | Интенсивность, длительность, область, читаемость | Контекстный брендовый фрагмент; ошибка — постоянные сбои всех текстов |
| Organic / procedural | Неравномерность по осмысленному правилу | Noise/поля/согласование, устойчивость и ограниченность | Живая графика; ошибка — случайные движения без связи с брендом |

Gooey, morph и liquid — способы визуального преобразования, которые могут иметь smooth или sharp timing. Простая пружина не делает morph; blur не делает gooey без геометрической связи. Термины пользователя уточняй через конкретный вариант для его материала, не заставляя выбирать технический словарь.

## 3. Карта семей: компоненты и изменения

Разновидности в строке — кандидаты, а не список того, что нужно добавить на сайт. Одно решение часто объединяет несколько семей. Выбор сверяется с назначением, стилем, стеком и реальным материалом.

| Семья | Варианты и полезные поисковые слова | Условие приёмки / характерный провал |
| --- | --- | --- |
| Вход и выход | Fade; fade-slide; scale; grow from anchor; masked wipe; clip reveal; curtain; stagger; text/image reveal | Контент и действие доступны вовремя; всё не появляется одинаково снизу и не остаётся навсегда opacity:0 |
| Последовательное раскрытие | Line/word/character reveal; masked lines; split text; typewriter; scramble-to-readable; count-up | Реальный текст, переносы, доступное представление; обязательный абзац не надо ждать по буквам |
| Диалог и popup | Overlay fade; panel scale; anchor expansion; sheet; drawer; zoom from source; shared element | Фокус, Escape, закрытие и scroll lock работают; анимация не заменяет семантику |
| Dropdown / popover / tooltip | Origin-aware scale; slight directional slide; crossfade; submenu continuity; collision-aware side | Направление после flip соответствует реальному положению; pointer не теряет раскрытие на пути к нему |
| Expand / collapse | Измеренная height/width; layout reflow; reveal внутри; accordion; disclosure; expanding card | Текст не растянут вместе с рамкой, динамический контент не обрезан, обратный ход существует |
| Layout / reorder | FLIP; shared element; card-to-detail; masonry rearrange; list insert/remove; filter/sort transition | У объекта сохраняется идентичность, нет двух владельцев transform и прыжка после завершения |
| Замена / swap | Crossfade; directional slide; flip; slide-stack; shared layout; icon/number swap | Изменившийся смысл понятен, исходный/новый текст не конкурируют в озвучивании |
| Hover / focus / press | Highlight; underline travel; color; elevation; small scale; image crop; ripple; pressed depth | Действие мгновенно узнаваемо и доступно клавиатурой/touch; нет hover-only функции |
| Interactive pointer | Follow; magnetic detail; tilt; parallax card; spotlight; cursor effect; proximity reactions | Указатель и цель согласованы; нет второго конкурирующего курсора или ловушки движения |
| Drag / swipe | Direct manipulation; resistance; elastic constraints; inertia; snap-to-point; reorder; swipe-dismiss | Во время drag объект следует вводу, после release поведение ограничено; путь удаления обратим по задаче |
| Range slider | Thumb move; filled track; marks; tooltip; snap; multi-thumb; radial control | Thumb, track и value синхронны в обе стороны; damping не делает значение запоздалым |
| Carousel / gallery slider | Slide; crossfade; stacked cards; scale center; thumbnail sync; drag+snap; continuous marquee | Next/prev, клавиатура и остановка autoplay; скрытые slides не остаются ошибочно доступными |
| Toggle / switch / checkbox | Thumb travel; track fill; icon/check draw; press compression; segmented selection | Состояние и label стабильны, быстрое повторное переключение не ломает конец |
| Tabs / segmented controls | Sliding active indicator; crossfade panel; directional panel; layout-size interpolation | Активный индикатор соответствует tab, layout и фокус не прыгают при разной длине |
| Top nav / sidebars / bottom bars | Menu panel shift; active pill; hide/reveal header; drawer; collapse-to-rail; dock magnification | Сохраняются текущий раздел, доступ к действиям и безопасная область мобильного устройства |
| Progress / stepper | Determinate fill; radial arc; segmented steps; reading progress; stage transition | Реальное значение не подменено выдуманными процентами; сглаживание не показывает ложное завершение |
| Loading / pending | Indeterminate spinner; pulse; skeleton; shimmer; dots; staged placeholder; progressive content | Pending связан с операцией; skeleton отражает будущую структуру, error/empty/timeout не спрятаны |
| Feedback / status | Toast enter/exit; success mark; restrained shake; attention pulse; save indicator | Ошибка объяснена текстом, успех не выдуман, toast не исчезает до нужного действия |
| Векторы | Stroke draw/erase; moving dash; path-follow; morph; mask fill; gradient movement; animated icon | Stroke и fill различаются, контур узнаваем, конечная форма проверена |
| Изображение / media | Crossfade; pan/zoom; reveal crop; displacement; frame sequence; poster→video | Контент не перекрывает чтение; offscreen/media lifecycle и fallback определены |
| Фон / материал | Gradient drift; mesh; grain; particles; waves; shader; fluid field; glow response | Роль в композиции и нагрузка определены; нет набора несвязанных бликов |
| Данные | Enter/update/exit marks; bar growth; line draw; axis rescale; number tween; highlighted series | Значения и сравнение остаются достоверными; движение не делает промежуточное число реальным измерением |
| Route / page / view | Crossfade; push/pop; shared object; reveal; transition snapshot; skeleton handoff | История/Back, scroll restoration и focus сохранены, завершение не блокирует навигацию |
| 3D / spatial | Camera move; orbit; explode; rotation; pose; material transition; object follow | Motion задаёт сценарий, специалист 3d — сцену; нет бессмысленного вращения модели |

Для функций input различай range slider и carousel: у них разные задачи, значения и клавиатура. Это закреплено в [APG Slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/) и [APG Carousel](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/). Аналогично switch — бинарный input, не любая анимированная кнопка. Сохранение его label при смене state разъясняет [APG Switch](https://www.w3.org/WAI/ARIA/apg/patterns/switch/).

## 4. Кривые, spring и inertia

### Время и путь — разные функции

Easing отображает прогресс анимации в прогресс значения; пространственный Bézier path задаёт траекторию. Одни и те же четыре числа не определяют одновременно обе вещи. У движения могут быть отдельно duration, delay, путь, easing по свойствам, stagger и end-state. [CSS Easing Functions Level 2](https://www.w3.org/TR/css-easing-2/) описывает преобразование прогресса, а не универсальный характер бренда.

### CSS cubic-bezier

В `cubic-bezier(x1,y1,x2,y2)` начальная/конечная точки timing-функции фиксированы (0,0)/(1,1), x1/x2 должны принадлежать [0,1]. y может выходить из диапазона и давать overshoot; свойства с ограниченным диапазоном могут его обрезать. Кривая не описывает движение по двумерной дуге. `ease-in` ускоряет от начала, `ease-out` замедляет к цели, `ease-in-out` сочетает обе фазы; выбери смысл под вход/выход/перемещение, а не один ease всему UI. [MDN cubic-bezier](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/cubic-bezier).

Временная кривая с сильным overshoot может подходить position/rotation, но стать странной для opacity и цвета. Сравни одинаковый объект/путь при разных кривых и проверь остановку. Резкое появление не требует ease-in, который сначала скрывает реакцию пользователя.

### Linear, linear() и steps

`linear` — постоянная скорость интерполяции. Функция `linear(...)` — кусочно-линейная карта с несколькими опорными точками; она может приближать bounce/spring, а не только равномерное движение. Это запечённый профиль: текущая скорость drag автоматически не подставляется в него. [MDN linear()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/linear).

`steps(n, jump-...)` создаёт дискретную последовательность с выбранным расположением скачков; уместна sprite/механическому движению, но не должна превращать обычную плавную загрузку в визуальные лаги. Подбирай кадры и endpoint под конкретный материал. [MDN steps()](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function/steps).

### Пружина и инерция

Physics spring описывается жёсткостью, затуханием, массой и начальной скоростью. Большая damping уменьшает колебания; непрерывная retargeting-анимация может учитывать текущую velocity. Duration-based spring удобна для заданной видимой длительности, но не равна физической модели с передачей скорости. В Motion `stiffness/damping/mass` переопределяют duration/bounce; не смешивай обе конфигурации, ожидая независимого действия всех параметров. Inertia продолжает движение от release velocity, затем замедляет; границы/snap задаются отдельно. [Motion transitions](https://motion.dev/docs/react-transitions).

Практически сначала определи цель: drag-release требует непрерывности с вводом; короткий state change — понятного установления; бесконечный spinner — ровной фазовой скорости. Пружина не должна бесконечно дрожать из-за нулевого затухания/неверного rest threshold. Проверяй крупную и малую дистанцию, быстрое изменение target, возврат и повтор. Готовый CSS-профиль spring не гарантирует физическую непрерывность после прерывания.

### Семейства easing для расширенного поиска

В [GSAP Ease Visualizer](https://gsap.com/docs/v3/Eases/) есть семейства Power, Sine, Expo, Circ, Back, Elastic, Bounce, а также CustomEase и другие профильные инструменты. Их имена — варианты профиля, а не предписание UX. Более сильный power — иной ход значения; back добавляет предвосхищение/overshoot, elastic и bounce дают специфическую возвратную пластику. Сравниваемый исходник и разрешённый пакет важнее узнаваемого имени preset. Не называй easing физически достоверной симуляцией только по сходству траектории.

### Продолжительность и токены

Duration зависит от расстояния, размера/площади, задачи, частоты использования, устройства и координации. Настрой небольшую систему ролей `instant/feedback/disclosure/layout/scene` либо принятую модель проекта; это семантические категории, не обязательные значения. У мелкого частого действия обычно важнее быстрый видимый отклик, чем церемония. Долгий выразительный кадр может быть допустим, когда он не удерживает основное действие. Не закрепляй 150/300/500 ms как закон каждой реализации и не копируй duration учебного примера без сравнения.

## 6. Подробности, которые легко спутать

**Morph и shared layout.** Перемещение/масштаб одного прямоугольника между состояниями не обязательно морфинг контура. Для SVG `d` обычная интерполяция требует совместимых команд/структуры; отличающимся формам нужен подходящий mixer/нормализация. [Motion path morphing](https://motion.dev/docs/react-svg-animation#path-morphing). Сохраняй исходную геометрию брендового знака, если она задана; анимация не разрешает перерисовать её наугад.

**Gooey.** Один распространённый способ — размыть alpha нескольких форм, затем усилить её порог через цветовую матрицу; это создаёт мягкие соединения. [SVG feGaussianBlur](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feGaussianBlur), [feColorMatrix](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feColorMatrix) — технические примитивы, не готовый UX-компонент. Такая композиция — пример синтеза, не обещанный эффект отдельной команды. Не пропускай через blur читаемый текст и интерактивные границы; измерь площадь фильтра/paint и дай устойчивый вариант.

**Floating.** Циклическое перемещение по синусоиде/замкнутому пути и spring-following указателю — разные источники движения. [Motion useTime](https://motion.dev/docs/react-use-time) даёт elapsed time для процедурного цикла; он не задаёт автоматическую паузу offscreen или смысл бренда. Ограничь амплитуду и область, определи pause/reduced вариант; не превращай кнопку в плавающую цель.

**Page transition.** Native [View Transition API](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API) может анимировать представления между состояниями/навигацией в поддерживаемом контексте. Snapshot-transition не равен живой layout-анимации и сам не решает focus/history/scroll restoration. Проверь целевые браузеры и fallback; одинаковая оболочка не обязательна всему продукту.

**Loading и progress.** Loader сообщает pending, progress — измеренный ход, skeleton — будущую структуру. Не подменяй долгую операцию фальшивым 99% и не держи уже готовый ответ ради минимальной длительности. Сглаживание показателя может смягчать скачок, но реальный статус/доступное значение не должен обещать неверное завершение. При быстрых операциях оцени предотвращение flicker отдельно, без универсального порога задержки.

**Обратимость.** Для hover, dropdown, toggle, slider, accordion и shared transition определи не только вход, но выход/возврат, повтор, отмену и target при прерывании. Технически гладкий первый прогон ещё не подтверждает отзывчивость компонента. Input не блокируется до конца декоративной анимации; визуальный остаток не должен перехватывать события после закрытия.

## 7. Как агент превращает карту в решение

1. Назови конкретную задачу посетителя и существующий компонент/материал. Если проблема локальная, не назначай новую motion-идентичность всему сайту.
2. Выбери семью и реальные состояния. Опиши ожидаемый первый отклик, готовность действия, reverse/interruption и спокойный вариант.
3. Подбери характер под бренд и контекст, затем техническую модель. Вопрос пользователю нужен для существенной неизвестной развилки: например, точный рабочий отклик или мягкий выразительный акцент на данном объекте. Не спрашивай «smooth или morph», как будто они исключают друг друга.
4. Сформируй поисковый профиль: компонент + функция + характер + модель/стек + устройство/ограничение. Пример для формы: `origin aware dropdown restrained React keyboard exit interruption`; для знака: `SVG path draw reversible logo stroke`. Это пример построения запроса, не одна строка для каждого бренда.
5. Изучи подходящие варианты по внутренним страницам и исходникам; возьми механизм из эталона, не оформление всей демонстрации. Сравни исходные open/close, responsive, reduced, repeated use и зависимости до принятия.
6. Собери настоящий компонент с его семантикой и состояниями. Движение подключается к реальному состоянию; не делай demo-значение отдельным от рабочего input.
7. Проверь быстрые противоположные действия, путь через клавиатуру/touch, длинное содержимое, resize и lifetime. Отдельно оцени видимый результат и производительность в целевой среде; опубликованный исходник и документация не доказывают smoothness на устройстве.

Матрица показывает, что исследовать, а не что навязать. Для конкретного scroll-сценария нужен отдельный разбор типа прокрутки/привязки; наличие motion-скилла само по себе не добавляет parallax, scroll-jacking и длинные pinned сцены.
