# От найденного приёма к работающему компоненту

Сначала прочитай затронутую ветку [таксономии](taxonomy-and-timing.md), для прокрутки — [scroll-системы](scroll-systems.md). Программные источники и получение кода — [source-access](source-access.md). Этот справочник связывает материал со сценарием, состояниями, реализацией и проверкой. Внешний bundle или screenshot не являются исходным компонентом с разрешением на перенос.

## 1. Предметный поиск

Запиши задачу посетителя, существующий компонент/сцену, нужное изменение, контекст макета, ввод и принятый характер. Затем сформируй запрос по независимым признакам:

`роль + поведение/механика + характер + среда/ограничение`.

Например, для компактного рабочего меню исходный профиль: dropdown, source/collision-aware enter/exit, restrained fast-settling, keyboard/touch, текущая React/Radix-система. Для визуального портфолио другой: selected project → detail, shared media continuity, deliberate editorial, native scrolling, responsive image. Это конкретные следствия задачи, не два обязательных пресета.

Отдельно ищи названия механики: `accordion auto height interruptible`, `direction aware navigation menu`, `svg path draw`, `drag carousel snap`, `scroll linked image reveal` и нужные вариации. Эстетические слова помогают отбору, но не заменяют функцию и её полный цикл. У ресурса может быть семантический поиск вместо тегов; используй его настоящую схему, не добавляй вымышленные параметры.

Путь отбора: тематический каталог/документированный поиск → релевантные внутренние страницы → изучение нескольких действительно различных пригодных кандидатов → сравнение выбранного свойства и компромиссов → код/зависимости/лицензия → адаптация в свой макет. Не заканчивай на первом работающем примере и не считай одну и ту же библиотеку на двух зеркалах двумя альтернативами. Увеличивай глубину, пока конкретный пробел не закрыт; фиксированная квота посещений не доказывает качество.

Сравнивай не только красоту эффекта, но и частоту действия, плотность, семантику, мобильный сценарий, reverse/interrupt, поддержанный стек, reduced motion и стоимость интеграции. Свойство «gooey» не оправдывает плохое меню, а спокойный рабочий dropdown не закрывает заказанную выразительную историю. Из прежнего проекта можно повторно использовать проверенную техническую основу; характер и выбранный эффект выводятся заново из текущего брифа.

## Непрерывность чтения, ввода и состояния

Для любого дизайн-кода выбирай выразительность вместе с частотой операции. Частое обновление фильтра, ввода или данных не должно повторно проигрывать вступление и заставлять заново искать объект; выразительный переход контекста может иметь другой ритм. Одна общая грамматика не требует одной кривой/длительности всех ролей, а разнообразие не требует отдельного эффекта каждой кнопке.

Анимируй переход логического состояния, сохраняя нужные ID, focus, selection, незавершённый ввод и медиа-контекст. Удаление/пересоздание DOM и красивый exit не оправдывают тихую потерю поля вне главной формы. Сохранение, черновик, отмену или предупреждение согласуй с контрактом продукта, без автоматического добавления autosave. Поздний запрос и старое завершение анимации не меняют новую сущность/операцию; проверяй быстрый повтор, возврат, выход со страницы и cleanup вместе с reduced-вариантом.

## 2. Контракт движения

До сборки сложного компонента определись с относящимися полями; одной microinteraction достаточно короткой заметки, не новой бюрократической формы:

| Поле | Что определить |
| --- | --- |
| Роль | Что движение сообщает или позволяет сделать; нужен ли вообще переход |
| Состояния | Исходное/целевое, entering/open/exiting/closed, pending/success/error, dragging/releasing/rest при наличии |
| Источник | Pointer, keyboard, focus, touch, реальные данные, viewport, scroll progress, время, media |
| Геометрия | Origin, anchor, направление/дистанция, размеры, область и координатная система |
| Время | Tween/spring/inertia/steps/timeline; задержка, settle, sequence и повтор по смыслу |
| Прерывание | Retarget/reverse/cancel/replace/queue — что соответствует операции, кто владеет состоянием |
| Среда | Ширины/контейнеры, RTL при необходимости, nested scroll, platform, supported versions |
| Доступный вариант | Уменьшение движения, клавиатурный/touch-путь, focus и semantic state |
| Проверка | Конкретный цикл/пограничное условие и наблюдаемый ожидаемый результат |

Новый дизайнерский вопрос задавай только там, где неизвестное меняет результат: например, нужна ли последовательная история или свободный доступ ко всем работам; движение предмета показывает устройство или создаёт атмосферу; насколько физичный характер допустим в частом действии. Варианты проектируются под содержимое с последствиями и рекомендацией. Если scroll уже заказан, уточняй оставшийся сценарий, а не «нужен ли scroll». Если движение делегировано — решай в пределах задачи. Не спрашивай параметры stiffness или Bézier у пользователя вместо дизайна.

## 3. Выбор технической основы

| Потребность | Подходящая начальная основа | Ограничение |
| --- | --- | --- |
| Несложный hover/pressed/color/opacity | CSS transition/keyframes в текущем компоненте | Не `transition:all`; различай hover/focus/active и отсутствие hover на touch |
| Независимый воспроизводимый clip с playback/reverse/cancel | WAAPI в подходящем стеке | У каждой animation есть lifecycle; animation.finished может reject при cancel |
| React layout/presence/gestures, текущее приложение использует Motion | Motion и семантический primitive | Не заменяй готовый accessible primitive самодельным div ради анимации |
| Сложная согласованная timeline, pin/scrub и измерения сцены | GSAP/ScrollTrigger, когда выбранная задача это требует | Scope/cleanup/refresh и координаты обязательны, не общий триггер всему сайту |
| Progress/reveal, связанный с нативной прокруткой | CSS scroll/view timeline при поддержке или подходящая текущая библиотека | Feature detection, читаемый fallback, настоящая геометрия/overflow |
| Переход между представлениями/страницами | Existing router/layout solution, FLIP/shared element или View Transitions | Нельзя добавлять новый роутер и двойные snapshot/FLIP эффекты ради одного перехода |
| Авторская векторная/сценарная анимация | SVG/WAAPI/GSAP, Lottie или Rive по формату и состояниям | Renderer, ассеты, лицензия и состояние контролов проверяются отдельно |

Документация основ: [WAAPI](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API/Using_the_Web_Animations_API), [Motion layout](https://motion.dev/docs/react-layout-animations), [AnimatePresence](https://motion.dev/docs/react-animate-presence), [View Transitions](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API). Проверяй версию и актуальную поддержку; встроенная возможность не делает миграцию стека оправданной. Наличие CSS или GSAP само по себе не означает быстрый рендер.

## 4. Состояние важнее декоративного таймера

Подтверждённое действие меняет semantic state сразу по логике продукта; анимация изображает его. Не связывай реальное завершение загрузки с красивым трёхсекундным таймером. Не держи кнопку неработающей до конца обычного hover. Для drag визуал должен следовать вводу, а вторичный наклон/шлейф может отставать в пределах выбранного характера. Наклон от скорости должен учитывать знак и успокаиваться при остановке; одинаковый pressed-отклик вправе не кодировать направление.

Прерываемый переход начинается из текущего видимого состояния и идёт к новой цели, если это смысл операции. Накапливающаяся очередь hover/open/close делает UI запаздывающим. Очередь допустима там, где действительно нужно показать последовательные операции. При reverse пружина, tween и timeline могут требовать разной логики; одинаковый вход/выход не является универсальным правилом. Сохрани непрерывность там, где она важна, без требования физической скорости каждой декоративной сцены.

Проверь: открыть → закрыть до завершения → открыть снова; перейти дальше → сразу назад; drag → сменить направление → отпустить; выйти из области/потерять pointer capture → вернуться; сменить route во время transition. Обработчик старого clip не должен закрыть новое актуальное состояние. При WAAPI обработай отмену `finished`/cleanup; бесконечный fill и забытые animation objects не являются состоянием приложения. [Animation.cancel](https://developer.mozilla.org/en-US/docs/Web/API/Animation/cancel).

## 5. Компонентные условия

В новом порученном UI применимые раскрывающиеся поверхности и состояния управления обязательны к реализации, а не только описанию. Не ожидай отдельного запроса на dropdown, overlay, mobile drawer или pending/error формы, если они следуют из сценария. Адаптируй готовую основу под типографику/плотность/цвет/геометрию проекта: trigger + открытая панель + выбранное/hover/focus/disabled по роли, backdrop/слои для модальности и прямой/обратный transition. Семантика остаётся у правильного primitive, кастомность оценивается по целой поверхности. Дефолт библиотеки без адаптации, скачок непроработанного нового раскрытия и отсутствующий exit оставляют работу незавершённой. Мгновенный режим/reduced применяется осмысленно; native/system исключение имеет конкретное основание. На исправлении принятого компонента не затрагивай остальной дизайн.

- **Popup, dialog, dropdown, popover, tooltip, drawer.** Выбери правильную функцию: action-menu, navigation disclosure и modal dialog не взаимозаменяемы. Сохрани привязку/transform-origin и collision direction. Lifecycle exit должен согласовать DOM, pointer events, inert и focus; `opacity:0` не делает содержимое недоступным для Tab. `forceMount` без управления hidden/focus не готовая интеграция. [Radix animation](https://www.radix-ui.com/primitives/docs/guides/animation) показывает механизм отложенного unmount, не заменяет проверку семантики.
- **Expand/accordion.** Естественная высота, динамический контент, шрифты/изображения и повторное открытие не должны обрезаться. `max-height:1000px` даёт зависимость реальной длительности от длины и потолок; это не точное решение любой высоты. CSS `interpolate-size`, измерение или библиотечный layout выбираются по поддержке; проверь clipping, padding и рост содержимого. Отдельно контролируй visibility/focus закрытого блока. [interpolate-size](https://developer.mozilla.org/en-US/docs/Web/CSS/interpolate-size).
- **Tabs, switch/toggler, swap, nav/sidebar/bottom bar.** Сначала меняются выбранное состояние и содержимое, indicator помогает найти связь. Движение по расстоянию/направлению не должно менять baseline текста или блокировать следующее действие. Drawer отличается от sidebar, который остаётся в layout; dock-увеличение не подходит всем bottom-nav. Проверяй маршруты/Back/active state и safe-area, если они относятся к компоненту.
- **Range slider и carousel — разные сущности.** У первого value/step/min/max и геометрия thumb/track, у второго index/items и навигация/drag/snap. У range проверяются крайние значения, keyboard и RTL; у carousel — оба направления, быстрый повтор, drag cancel и скрытые slides. Не заставляй pointer ждать trailing spring, который изображает значение неточно.
- **Progress, loading, skeleton.** Determinate получает настоящие данные; неизвестную длительность изображает indeterminate. Не рисуй фиктивные 95% ради динамики. Skeleton соответствует будущей структуре, не мерцает постоянно и не создаёт layout shift. Loading может начаться с краткой отсрочкой против flicker, только если это не скрывает реальное ожидание; правило задержки выбирается под сценарий, не вечный таймер.
- **SVG draw/morph.** Отрисовка stroke и изменение `d` — разные техники. У draw учитываются длина/offset/pathLength и caps; у morph — совместимость геометрии, subpaths и выбранный solver. Crossfade двух иконок не называется буквальным path morph. Сохраняй смысл/доступное имя и конечный логотип, не искажай утверждённый бренд ради эффекта.
- **Float, magnetic, tilt, trail, interactive background.** Движение получает anchor, пределы, покой, реакцию на уход и поддержку без pointer. Не позволяй цели убегать, не включай tilt на основной текст и не заводи второй активный указатель. Декоративный follower не требует скрывать системный курсор; осознанная замена имеет обычный безопасный вариант.
- **Reorder, add/remove, drag/drop.** Сохраняй identity/key, роль, focus и результат операции; визуальный порядок не должен противоречить чтению и доступной навигации. Источником истины служат данные, а не координаты animation-frame. Перемещение имеет альтернативный путь ввода.

Для собственного drag/swipe на Pointer Events задай владение жестом до его начала: `touch-action` разрешает нужный native pan/zoom, пока компонент обрабатывает свою ось. Не отключай pan/zoom всей страницы ради одного carousel. При необходимости захвати pointer на время жеста, освободи при завершении; обработай `pointercancel`/`lostpointercapture`, уход/unmount и очистку временного состояния. Отмена не должна подтверждать удаление/перемещение как успешный release. Проверь прерванный touch-drag и вертикальную прокрутку поверх горизонтальной ленты. [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action), [setPointerCapture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture), [pointercancel](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointercancel_event).

## 6. Цвет и типографика во времени

Color задаёт палитру и light/dark, typography — набор; motion отвечает за путь между принятыми состояниями. Концы анимации могут проходить контраст, а середина — нет. Особенно опасны одновременный переход текста и фона, crossfade двух противоположных тем и градиент, проходящий под строкой. При необходимости раздели слои/фазы, удержи читаемую поверхность или меняй функциональный текст без интерполяции. Не добавляй кислотный промежуточный акцент ради «живости».

Укажи пространство интерполяции и hue-path, если эффект от них зависит. CSS, SVG, canvas и библиотека могут смешивать цвета по-разному; `in oklch` внутри градиента не настраивает автоматически JS tween цветов. Убедись, что формат поддерживает выбранный путь, alpha и gamut. Перцептуальное пространство помогает управлять цветом, но не гарантирует контраст и отсутствие нежелательного hue. [CSS color interpolation](https://developer.mozilla.org/en-US/docs/Web/CSS/color-interpolation-method).

Анимация текста не должна ломать shaping, лигатуры, RTL, диакритику и копирование. Split по code units не эквивалентен графемам, а правильная графема не всегда сохраняет соединение слова. При kinetic typography проверь реальную локаль и доступное текстовое представление без двойной озвучки. Лёгкий blur не заменяет вариант без пространственного движения; поддерживай читаемое устойчивое состояние.

## 7. Исполнение, производительность и приёмка

У свойства/элемента один владелец: CSS hover, Motion layout, GSAP scrub и сторонний component не должны одновременно писать один transform. Раздели wrappers или каналы. В React scoped refs/cleanup, stable keys и lifecycle должны переживать повторный mount; не дублируй event listeners/ScrollTriggers/RAF на каждый render. Время RAF бери из timestamp, а не «один pixel на кадр»; при background/visibility и возврате согласуй clock. [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame).

Transform/opacity часто дешевле свойств layout/paint, но это приоритет выбора, не запрет на необходимые height/color/stroke. FLIP может искажать масштаб текста/границы; крупный blur, SVG filter и много слоёв могут быть дороги. Ставь `will-change` только по необходимости и освобождай ресурсы; GPU/120Hz не обещаются по CSS-свойству. Измеряй проблемный участок, idle/interaction и поддерживаемую среду. [web.dev performance](https://web.dev/articles/animations-guide).

Приёмка должна воспроизвести задачу: initial/прямой вход → действие → выход/обратный ход → прерывание → покой → повтор; затем нужные keyboard/touch, узкая/промежуточная ширина, resize/динамический контент, reduced motion, loading/error и cleanup. Авто-тесты проверяют состояние и geometry в своей области, настоящий render — видимость/ритм/отклик, performance trace — исполнение в названной среде. Сам факт использования готовой библиотеки и описание автора не закрывают ни одну из этих проверок автоматически.

Передавай выбранный источник/версию, извлечённое свойство, полный комплект/лицензию, изменения относительно донора, motion tokens и state contract, measured/observed результаты и оставшиеся ограничения. Если рендер не открыт, укажи `render_unverified`; если телефон не проверен, не обещай ему плавность. Выразительность оценивай в целой композиции вместе с design; исправляй проблему и повторяй затронутые проверки, не весь бриф.
