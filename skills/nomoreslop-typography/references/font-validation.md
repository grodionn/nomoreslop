# Проверка письменностей и выбранного файла

Это квалификация источников, файлов, письменностей и фактического шрифта. Условия чтения проверяй отдельно по [сводке типографики](typography-rules.md) и [читаемости/доступности](readability-and-accessibility.md): успешные cmap и shaping не подтверждают контраст, удобный размер, интервалы и устойчивость страницы при увеличении.

Читай при квалификации шрифта, выборе script-компаньона и проверке подключения. Основной отбор — [font-research.md](font-research.md), доступные источники — [font-sources.md](font-sources.md). Выбирай проверки по фактическим локалям проекта; весь реестр Unicode не является обязательным корпусом каждого сайта.

## Письменности и локали

| Локаль / письменность | Что проверять сверх красивого specimen |
| --- | --- |
| `ru`, `Cyrl` | Настоящие строки, ё/Ё, й/Й, рисунок д/л/ж/ф, цифры и пунктуация; Latin-only образец не подтверждает русский |
| `kk-Cyrl`, `Cyrl` | Отдельно **Әә Ғғ Ққ Ңң Өө Ұұ Үү Һһ Іі**, действительные казахские строки и русские при наличии. `cyrillic`/`cyrillic-ext` — подсказки поиска, не гарантия. Для иной орфографии/письменности не придумывай транслитерацию |
| `vi`, расширенная Latin | Настоящие диакритики и их сочетания; высота знаков и строки; при вводе — используемые NFC/decomposed последовательности. `latin-ext` не обещает любой язык Latin |
| `el/Grek`, `hy/Armn`, `ka/Geor` | Реальные строки и нужные знаки/веса. Для Greek — применимые tonos/комбинации; не подменяй пропуски похожими латинскими буквами |
| `ar/fa/ur`, `Arab` | Корпус каждого языка, joining, применимые marks/лигатуры, числа и mixed Latin/URL. Arabic не тождествен Persian/Urdu; Nastaliq не выбирается автоматически. Tracking не должен разрывать связанный набор |
| `he`, `Hebr` | Реальные слова, числа/Latin, скобки и пунктуация; niqqud при наличии в материале. Правое выравнивание не реализует RTL |
| `hi/mr/Deva`, `bn/Beng`, `ta/Taml`, `te/Telu`, `kn/Knda`, `ml/Mlym`, `gu/Gujr`, `pa-Guru/Guru`, `si/Sinh` | Подходящие языку conjuncts, virama, перестановка и позиционирование гласных/marks. Наличие отдельных букв не подтверждает правильную последовательность |
| `th/Thai`, `lo/Laoo`, `km/Khmr`, `my/Mymr` | Сочетания над-/подстрочных marks, clipping, реальные переносы, выделение и ввод. Увеличение line-height не исправляет неверный shaping |
| `zh-Hans`, `zh-Hant`, `ja`, `ko` | Региональный файл/конфигурация, формы Han, относящиеся kana/hangul, пунктуация и переносы. Для поиска используются `Hani` и/или составные `Jpan/Kore`; один Unicode code point не задаёт единственный региональный glyph |
| Африканские языки Latin, `Ethi`, `Tfng`, `Adlm` и другие | Начни с конкретного языка/корпуса, а не общего «African». Дополнительные буквы и marks проверяются по тексту; Adlam также требует RTL. Noto/SIL — маршруты исследования, не обязательная одна гарнитура |

Коды ISO 15924, BCP 47, OpenType script tags и subsets распространителя не являются взаимозаменяемыми. В этой таблице перечислены контексты проверок, а не обещания определённого покрытия каждой гарнитурой.

## Корпус и роли

Сохрани настоящий заголовок, body-абзац, кнопку, форму/ошибку, длинное название, числа, цену/дату и реальный пользовательский ввод по применимости. Лингвистические тестовые последовательности отдели от канонического текста бренда. Не сочиняй якобы согласованный перевод ради specimen. При сомнении в привычных локальных формах нужна компетентная языковая оценка; техническую часть можно продолжать независимо.

Сравни роли в одинаковых условиях: одна и та же ширина/контент/состояние и воспринимаемый масштаб. Просмотри малый UI-текст и display в своих размерах, настоящий курсив, контраст и знаки на используемых фонах. Для data проверь различимость `0/O`, `1/l/I` при наличии этих знаков, цифры, знаки валют/минус, alignment и доступные `tnum`/`lnum` по задаче. Нужный OpenType feature проверяется на файле, а не назначается по названию.

## Инструмент маршрутизации и поиска

```text
python <skill>/scripts/font_catalog.py sources --script Cyrl --role body
python <skill>/scripts/font_catalog.py search --subset cyrillic --category serif --weight 400 --cache <new-cache.json>
python <skill>/scripts/font_catalog.py search --input <cache.json> --subset cyrillic --category serif --page 2
```

`sources` читает локальную карту без сети. Область источника не означает покрытие всех его файлов. Составные `Jpan/Kore` и `Hans/Hant` раскрываются в подходящие маршруты Hani/kana/hangul; это не автоматический выбор японской/корейской/китайской региональной формы. `search` использует публичный Fontsource endpoint и только документированные фильтры `subsets/category/weights/styles/variable`. Повтор `--subset`/`--weight`/`--style` требует всех перечисленных значений; это не OR. Фильтра конкретного языка, признака «editorial» или субъективной красоты у команды нет. Выполни следующие предметные обращения/изучение у авторов по результату.

Вывод постраничный: `total`, `has_more`, `next_page`, `page_size` (1–50). Алфавитный порядок ID не является рейтингом, а первая страница не завершает поиск. `--input` работает с локальным массивом либо сохранённым metadata-конвертом и прямо помечается cached; это не новый сетевой запрос. `--cache` сохраняет только новый явно названный файл, не перезаписывает существующий.

403/429/ошибка сети дают unavailable, не «шрифтов нет». На проверке 24 октября 2026 первый прямой запрос Fontsource вернул 403; последующий обычный запрос нового CLI успешно получил 68 metadata-записей по `cyrillic + serif` и сохранил cache. Доступность зависит от конкретного обращения и не гарантирована. При отказе перейди к открытому репозиторию Google Fonts/автора или другому источнику. Команда не делает автоматических повторов/обхода доступа, не устанавливает зависимости и не меняет системные шрифты.

Для конкретного Fontsource ID [документирован endpoint](https://fontsource.org/docs/api/font-id) `/v1/fonts/{id}`: используй реальные `variants` и существенные поля выбранного веса/style/subset. URL файла бери из ответа/manifest автора; не конструируй неизвестный путь по красивому названию. При недоступности этого канала его JSON не выдумывается.

## Бинарное покрытие

```text
python <skill>/scripts/font_catalog.py inspect <chosen.ttf> --text-file <actual-corpus.txt>
python <skill>/scripts/font_catalog.py inspect <collection.ttc> --font-index 0 --text-file <actual-corpus.txt>
```

Чтение бинарного файла требует имеющегося **fontTools**; WOFF2 может требовать **brotli**. Эти зависимости опциональны, скрипт их не устанавливает. Если окружения нет, используй доступное разрешённое окружение/ручную проверку и оставь недоказанное открытым. Корпус — UTF-8, максимум 1 MiB, font file — до 128 MiB, TTC/OTC требует явного face index.

Вывод включает SHA256, metadata names/version/license, оси fvar, наличие GSUB/GPOS и пропуски Unicode cmap конкретного face. Нулевой glyph/.notdef не считается покрытием. Форматирующие controls, CGJ и [variation selectors](https://www.unicode.org/Public/UNIDATA/PropList.txt) (включая Mongolian FVS) не объявляются отсутствующими видимыми буквами: они требуют проверки последовательности. Это ограниченный cmap-инструмент, не полный движок Unicode properties или layout. License metadata — указатель, не лицензионный допуск.

Если CSS делит семью на subsets, отдельно сопоставь реальную цепочку файлов/`unicode-range` и относящиеся им символы. Пропуск Cyrillic в Latin-subset закономерен, но не подтверждает наличие правильного Cyrillic-subset в приложении. Не объединяй чужие семьи, веса или fallback, чтобы скрыть пропуск выбранного face. Для каждого нужного начертания проверь его собственный набор и итоговую отрисовку.

`cmap_only` означает только отсутствие найденных пропусков в этом корпусе/методе; не «язык полностью поддержан». Cmap не проверяет правильность outlines, региональную форму, cmap14 variation sequences, локализованные подстановки, mark positioning и визуальное чтение. После subsetting/конверсии повтори на **итоговых байтах** и обнови хеши.

## Shaping и направление

При доступном HarfBuzz выполни реальный run с выбранным файлом, script/language/direction/features и относящимся текстом, например:

```text
hb-shape chosen.ttf --text-file=actual-arabic.txt --direction=rtl --script=arab --language=ar
```

Сначала проверь схему установленной версии инструмента. Не объявляй отсутствие `.notdef` доказательством правильных соединений, marks и привычной формы. HarfBuzz формирует glyph run; он не заменяет bidi layout абзаца, переносы и браузер/устройство. `lang` и `dir` решают разные задачи. Смешанные направления изолируй подходящей HTML-разметкой (`bdi`/`dir` по контексту), не перестановкой букв/пробелами. Для plain text правила bidi-controls имеют собственные границы.

Не разрезай cluster для split-text эффекта или обрезания. Запрет визуального шума не разрешает удалять диакритику, гласные знаки и ZWJ/ZWNJ, необходимые тексту. Для связанной письменности не считай независимые анимированные буквы безопасным вариантом по умолчанию.

## Настоящий вывод

На собственном локальном интерфейсе проверь текущую загрузку и **использованные** fonts на целевых элементах/фрагментах. При доступности подходят browser rendered-font tools или [CDP CSS.getPlatformFontsForNode](https://chromedevtools.github.io/devtools-protocol/tot/CSS/#method-getPlatformFontsForNode); это не обещание наличия CDP во всех средах. `getComputedStyle().fontFamily`, Font Loading API и `document.fonts.check()` дают другие ограниченные сведения. Один успешный запрос файла также не подтверждает использование.

Просмотри обычный/узкий кадр, увеличение текста, нужные веса и mixed-script, fallback во время загрузки/отказа, отсутствие обрезания marks и непредусмотренных скачков. Нативное приложение проверяется целевой платформой. Непроверенный рендер сохраняй открытым. Статический анализ, cmap и DOM-harness не заменяют кадр и действие.

## Основания

- [Google Fonts language metadata](https://googlefonts.github.io/gf-guide/lang) — выборка по языку, не визуальная оценка файла.
- [fontTools TTFont](https://fonttools.readthedocs.io/en/latest/ttLib/ttFont.html) — техническое чтение таблиц, не shaping.
- [HarfBuzz shaping operations](https://harfbuzz.github.io/shaping-operations.html), [clusters](https://harfbuzz.github.io/clusters.html) — формирование последовательностей.
- [W3C язык HTML](https://www.w3.org/International/questions/qa-html-language-declarations), [inline bidi](https://www.w3.org/International/articles/inline-bidi-markup/), [Arabic/Persian requirements](https://www.w3.org/TR/alreq/) — соответствующие условия и проблемы, не общий сертификат интерфейса.
- [Unicode CJK FAQ](https://www.unicode.org/faq/han_cjk.html) — региональные формы Han.
- [CSS Font Loading](https://www.w3.org/TR/css-font-loading/) — состояния загрузки и предел их интерпретации.
