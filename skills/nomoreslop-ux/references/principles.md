# Принципы UX и условия применения

Это общий канон решений, не универсальный визуальный шаблон. Применяй на уровне значения, компонента, состояния, страницы и связанного опыта. Сохраняй явный характер проекта: экспериментальная галерея и операционная форма могут иметь одинаково хороший UX разными средствами. Для обязательных критериев доступности устанавливай применимую платформу, уровень и исключения; эвристики не являются сертификацией.

## Основание решения

До компоновки установи намерение человека, важную информацию, результат и ограничение. Новичку нужна ориентировка, специалисту — эффективность; частота, неопределённость, цена ошибки и прерывание меняют подход. Подтверждённое требование, наблюдение и гипотеза отмечаются раздельно. Не придумывай интервью, метрики и модель пользователя. При отсутствии данных выбери обратимую рабочую гипотезу и укажи способ её проверки.

## Карта инвариантов

| Принцип | Как влияет на решение | Граница и проверка |
| --- | --- | --- |
| Понятность предмета | Покажи, где человек находится, что рассматривает и что доступно | Выразительная загадочность допустима в заданной художественной работе; критический смысл/выход не должны требовать угадывания |
| Соответствие ментальной модели | Группируй по задачам/объектам и понятным словам | Не строй навигацию по внутренним модулям организации без подтверждения; проверь поиск нужного раздела |
| Узнавание вместо лишнего запоминания | Дай рядом различия, выбранное, прошлый контекст и необходимые основания | Не показывай всё сразу; скрытые подробности должны иметь обнаружимый путь |
| Информационный приоритет | Свяжи порядок, пространство, масштаб и акцент с решением | Равноправный выбор допускает несколько равных объектов; один яркий CTA не обязателен |
| Группировка | Используй близость, общие края, названия и отношения интервалов | Карточка, линия и цвет — средства; не обводи каждое поле и не запрещай границы в плотных данных |
| Узнаваемая функция | Рисунок/подпись/семантика согласованы с результатом | Собственный стиль не оправдывает ссылку, которая неожиданно сохраняет, и кнопку без действия |
| Обратная связь | Покажи реальное изменение и следующий доступный шаг | Не нужен toast при уже очевидном результате; не выдумывай процент/успех |
| Контроль и свобода | Дай предусмотренный выход, отмену, изменение решения и возврат | Не требуй подтверждение любого действия; необратимое и дорогое защищаются соразмерно |
| Предотвращение ошибки | Устраняй неоднозначность, показывай последствия и зависимости заранее | Disabled имеет понятную причину/путь; форматирование не должно отвергать допустимый ввод без нужды |
| Восстановление | Сохраняй правильный ввод; различай ошибку значения, системы, прав и конфликт | Повтор не лечит отсутствие доступа, а сброс всего не является исправлением одного поля |
| Последовательность | Одинаковое намерение имеет согласованные название и поведение | Разные роли могут иметь разные компоненты; консистентность не означает одну компоновку всех страниц |
| Эффективность | Уменьшай лишние переходы, повторный ввод и поиск для задачи | Число кликов не единственный показатель; дополнительный обзор может уменьшать серьёзные ошибки |
| Доступность по вводу | Сохраняй клавиатуру, touch, видимый focus, labels и семантику | Hover не единственный путь к важному; ARIA-атрибут не реализует поведение |
| Непрерывность | Определи, какие выбор, место, объект и ввод переживают переход | Не сохраняй всё вечно; явный logout/reset и чувствительные данные имеют другие ожидания |
| Адаптация | Сохраняй возможность выполнить задачу при другой области/вводе | Простого складывания или отсутствия overflow может быть мало; размер устройства не равен ширине контейнера |
| Честный выбор | Условия, стоимость, последствия и альтернативы доступны до значимого решения | Не добавляй фиктивный дефицит, выдуманную популярность, скрытые доплаты и затруднённую отмену |
| Достаточность помощи | Объясняй неизвестное в контексте, с путём к подробностям | Тур не исправляет непонятную основу; сложному профессиональному инструменту обучение может быть нужно |
| Проверяемость | У решения есть ожидаемый наблюдаемый результат и граница | Документ/скриншот/сборка не подтверждают весь опыт; непроверенное не закрывается общей оценкой |

Основа общей эвристической карты — авторские [эвристики NN/g](https://www.nngroup.com/articles/ten-usability-heuristics/); их роль — выявлять риск и направлять проверку, а не выбирать размеры и гарантировать результат. Остальные решения этой карты — синтез правил комплекта и предметных паттернов; подробные основания и границы собраны в [источниках](sources-and-coverage.md).

## Практические развилки

Выбирай раскрытие вместо постоянного показа, когда подробность редка и не нужна для текущего решения. Показывай рядом, когда без сравнения человек вынужден помнить несколько экранов. Применяй последовательность, когда есть реальная зависимость или необходимость фокусироваться; сохраняй свободный доступ, когда порядок не важен. Не превращай сложность данных в обязательный wizard.

Сокращай не только количество элементов, но и число интерпретаций. Две ясные команды могут быть проще одного многозначного значка. Плотность и простор оценивай через чтение/работу; максимальная видимость всего и максимальное скрытие — одинаково неполные решения. Правила «не больше N пунктов», «три клика», «один экран», «всё важное выше сгиба», «44px для каждого элемента» не применяются без контекста и относящихся требований.

Выбранный стиль не отменяет общие инварианты. Менять можно средство: в галерее навигация может быть частью композиции, в кабинете — постоянной; в обоих нужен понятный предусмотренный доступ. UX не выбирает нейтральный минимализм как обязательную цену удобства.
