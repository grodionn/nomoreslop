# Управление, пути и состояния

Выбирай нужные разделы; отсутствие сценария не является недостающей функцией. Семантика, рисунок, данные и момент применения должны совпадать.

## Выбор контрола

| Намерение | Решение и критерий |
| --- | --- |
| Перейти / выполнить | Link для перехода; button для команды; menu для настоящих команд. Подпись и доступное имя соответствуют результату |
| Выбрать одно | Radio, segmented, select или combobox по длине, знакомости, месту, частоте и потребности видеть варианты; единого порога количества нет |
| Выбрать несколько | Checkboxes, listbox/multiselect и поиск по объёму; понятны выбранное, очистка и область «все» |
| Изменить булев параметр | Checkbox или switch по смыслу и применению: немедленно либо с общей командой; не обещай уже выполненное сохранение |
| Ввести / найти / создать | Различай свободный текст, фильтрацию фиксированных вариантов и новый тег; Enter, commit/cancel и no matches соответствуют режиму |
| Указать точное значение | Нужный тип ввода с единицами/границами; slider не единственный способ задать важную точность |
| Переключить / раскрыть | Tabs для контекста; disclosure для подробностей; не используй их вместо независимого множественного выбора |
| Упорядочить / переместить | Drag по задаче плюс требуемый доступный способ; клавиатура сама не заменяет применимую pointer-альтернативу |

В составном поле различай ввод, раскрытие, очистку и действие над набором. Проверь label/legend, доступное имя, hitbox и разное состояние дочерних целей. Native/semantic/headless primitive — подходящая основа; кастомный рисунок не требует переписать его keyboard и ввод. Предписания конкретной библиотеки о виде/числе вариантов не универсальны. Основания: [GOV.UK radios](https://design-system.service.gov.uk/components/radios/), [checkboxes](https://design-system.service.gov.uk/components/checkboxes/) и функциональные паттерны [APG](https://www.w3.org/WAI/ARIA/apg/patterns/); их внешний вид не обязателен другим проектам.

## Формы и многошаговые процессы

Собирай только необходимые продукту сведения; обязательность, формат, единицы и помощь понятны до ошибки. Поддерживай допустимый естественный ввод, autofill, password managers и paste по сценарию. Placeholder не заменяет устойчивую подпись; выключение HTML5-validation из конкретного паттерна GOV.UK не общий закон.

Для длинной формы выбери смысловые группы, шаги либо задачно-ориентированный список по зависимостям и возможности прерывания. Покажи, что необходимо, что сделано и что блокирует следующий шаг; не выдавай посещённый экран за заполненный. Не навязывай последовательность независимым задачам и не дроби каждое поле в отдельный шаг. Проверка ответов перед значимой отправкой может быть полезна, но не нужна каждой короткой форме.

Для условных полей/пресетов определи, какие значения меняются, что сохраняется при смене ветки и как видна ручная настройка. Невидимое невалидное поле не должно блокировать без объяснения; уничтожение введённого при смене условия также не автоматическое правило.

Различай ошибку конкретного ввода, недоступность сервиса, отсутствие права, истечение сессии и конфликт версии. Сохрани правильное, свяжи сообщение с местом/операцией, дай реальное исправление. Error summary полезен для нескольких проблем по контексту; один toast не всегда достаточен. После исправления фокус и продолжение предсказуемы. Основа восстановления — [GOV.UK validation](https://design-system.service.gov.uk/patterns/validation/), не его точная разметка для всех продуктов.

## Сохранность и обратимость

Охвати каждую изменяемую область, включая маленькое поле вне главной формы, выбранный файл и черновик сообщения. Определи local/dirty/pending/saved/conflict, срок сохранения и переходы: смена объекта/раздела, закрытие, Back, refresh, logout и предусмотренное прерывание. Выбери явное сохранение, autosave, черновик, отмену или предупреждение по ожиданию и последствиям. Не навязывай autosave и не сохраняй секреты вечно.

Undo восстанавливает результат операции, а не только внешний вид. Различай локальную отмену ввода, отмену запроса и компенсирующее действие после принятия. Не называй отправленное отозванным, когда система этого не умеет. Для опасного/дорогого действия ясны объект, последствия и подходящая защита; дополнительный modal не единственный способ. Перед необратимым действием применяются реальные условия авторизации среды.

## Поиск, фильтр и набор

Отдели запрос, фильтры, сортировку, выбранное и текущую страницу. Политика применить сразу/по кнопке определяется стоимостью и ожиданием, а не привычкой. Покажи область поиска, выбранные условия, число/статус результатов и сброс по нужде. Проверяй пустой запрос, нет совпадений, неизвестное, ошибку источника и устаревшие данные.

У multiple установи смысл пустого, all/partial и область «все»: совпадения, страница, каталог, коллекция. Поиск вариантов не должен молча менять уже выбранное; после «Ещё N» доступен полный обзор и удаление любого. Используй стабильные ID. При фильтре/сортировке/пагинации selection сохраняется или сбрасывается по понятной политике. Значение произвольного тега не равно ещё не подтверждённой строке поиска.

У таблицы/списка задай приоритет колонок/полей, ширины, формат, row action и сортировку всей предусмотренной области. Для batch покажи фактические охват, пригодность и исключения до действия соразмерно его последствиям. Отдельно проверь количество, идентичности и разные результаты. Сортировка не должна менять адресата операции. Команда выборки остаётся доступной в рабочем контексте; не добавляй функциональность сверх поручения.

## Асинхронность, уведомления и длительная работа

Свяжи запрос с объектом, параметрами и версией. Поздний ответ не перезаписывает новый контекст, закрытый слой и ввод; старое завершение анимации не отменяет новое открытие. Rapid repeat, timeout, cancel, retry, leaving view и повторное подключение проверяются по реальному контракту.

Различай принято/queued/running/completed/failed/skipped/unknown, локально/сервером сохранено и доставлено/прочитано, когда это важно операции. Не подделывай проценты; при неизвестной длительности показывай честное состояние. Частичный успех даёт нужное продолжение и не превращается в «всё готово». Повтор не дублирует выполненное; pause/stop/cancel имеют разные реальные последствия.

Уведомляй в нужном месте и срочности: inline, status, toast, inbox или blocking alert по последствиям. Не прерывай несущественным и не скрывай важное в исчезающем toast. Для динамики объявляй нужный краткий статус, не весь экран автоматически; см. [W3C Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). Документация/атрибут не подтверждают реальную работу assistive technology.

## Доступ, права и доверие

Если функция требует аккаунта, свяжи регистрацию/приглашение, повторный вход, истечение, выход и поддержанное восстановление. Сохраняй предусмотренный return target без утечки данных; отказ прав не маскируется пустым списком. Видимые команды и API соответствуют роли; ограничение объясняется в нужный момент. Парольная схема, гостевой checkout и magic link выбираются продуктом, не автоматически.

Проверяй используемые механизмы с учётом [Accessible Authentication](https://www.w3.org/WAI/WCAG22/Understanding/accessible-authentication-minimum.html), включая относящиеся помощь/альтернативы и исключения. Это не общий запрет паролей. Системное разрешение запрашивается в контексте полезного действия; отказ имеет доступное продолжение. Не заказывай новые роли, CAPTCHA и permissions ради полноты списка.

Существенные цена/комиссия, период, автопродление, условия и последствия видны до соответствующего решения. Не выдумывай экономию, scarcity и social proof; отмена и отказ не должны намеренно затрудняться. Внешний платёж/отправка/публикация следуют разрешениям среды, UX-анализ не даёт отдельной авторизации.

## Пространственное, offline, совместное и AI

Для canvas, карты, reorder и жестов обеспечь обнаружимость и нужное альтернативное управление; системные жесты и прокрутка не должны беспричинно конфликтовать. Для web drag учитывай точные условия [W3C Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html); обычная прокрутка не авторский drag.

Когда offline/совместная работа входят в продукт, различай локальную правку, отправку, подтверждение, конфликт и потерянное соединение; покажи способ восстановления без ложного успеха. Пользователь должен понимать, чья версия/selection видна и что изменил другой участник. Не обещай офлайн-хранение, real-time или Undo удалённого состояния, которого нет.

Для заказанной AI-функции определены вход, ход, остановка, происхождение/неопределённость, исправление и принятие результата. Сохраняй исходный ввод и контроль; сгенерированный текст не равен проверенному факту и не публикуется автоматически из-за красивого превью. Не добавляй AI чат вместо подходящего обычного поиска/формы без основания.
