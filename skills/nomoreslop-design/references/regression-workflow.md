# Выборочные регрессии известных ошибок

Проверяй текущий результат по изменённой задаче. Каталог описывает сценарии проверки, а не уже выполненные тесты и не детектор AI-авторства. Один приём, слово, шрифт или цвет не определяют происхождение интерфейса. Применимость, исправление и граница живут в канонической записи `antipatterns/`; этот процесс помогает проверить её на артефакте.

## Выбор и чтение

1. Прочитай актуальные бриф, содержание, принятые решения и затронутую реализацию. Назови, что изменилось: текст, количество объектов, материал, геометрия, механика, интеграция либо платформа.
2. По [индексу](antipattern-index.md) выбери относящиеся ID. Прочитай их через `python <путь-к-скиллу>/scripts/library.py show ID...`, затем сценарии через `python <путь-к-скиллу>/scripts/library.py checks ID...`. Дочитай страницы, указанные в выводе; не загружай все 163 записи ради одного контрола.
3. Проверь условие и границу канона. Выбери настоящий экран, объект и данные; уточни конкретное действие и наблюдаемый результат. Условие, которого нет в задаче, не превращай в обязательную новую функцию.
4. Выполни сценарий и проверь корректный контрольный пример. Если фильтр требует удалить нужную подпись, рабочую таблицу, стандартный контрол или авторскую цитату, исправь применение правила.
5. Исправь найденную причину и повтори затронутый сценарий. Сохрани вывод по текущей версии. Уже подтверждённые несвязанные свойства не перепроверяй без нового основания.

Без Python открой нужное семейство и найди ID в [pattern-checks.json](pattern-checks.json). Поля `canonical.path` и `canonical.anchor` указывают запись внутри `references/`; якорь соответствует полному Markdown-заголовку. `check.action` задаёт действие, `expected` — наблюдаемый результат, `counterexample` — корректный случай, который правило не должно отвергать. Поля проверки не являются копией канонического исправления и границы. При уточнении правила проверь, что связанный сценарий остался пригоден.

## Что считается свидетельством

В текущем `design-state` запиши ID/проверяемое свойство, версию или хеш затронутых файлов, экран/объект/состояние, действие, наблюдение, способ и существенный предел. Отдельный дублирующий журнал не требуется. Используй фактический статус: требуется, пройдено, найдена проблема, недоступно или не применимо с причиной.

- Для текста сопоставь канон с реальными строками и состояниями. Статический сбор даёт кандидатов; видимость, текст изображения/canvas и системные сообщения требуют отдельного просмотра либо честного ограничения метода.
- Для функции выполни действие на нужных данных, включая относящиеся ошибку, возврат, повтор и прерывание. Скриншот не доказывает изменение данных, историю или доступность клавиатуры.
- Для ремесла нужен реальный рендер текущих стилей, шрифтов и ассетов в нужной области экрана. DOM с размерами-заглушками не подтверждает оптическое выравнивание, чтение, слои или плавность.
- Для происхождения раздели получение материала, его включение и сохранение выбранного свойства. Непустой исходник не доказывает использование; адаптация другим кодом может сохранять механику.
- Для актуальности свяжи свидетельство с файлами и состоянием. Замена hero открывает её текст, композицию, материал и поведение; исправление одной подписи не отменяет несвязанный тест навигации.

Известная проблема основного порученного маршрута требует исправления до утверждения о готовности. Недоступный рендер остаётся открытым результатом проверки; продолжай независимую работу. Публикация не подтверждает качество и не создаёт нового согласования уже порученного действия. Подробные области оценки — [review.md](review.md), условные платформенные маршруты — [platform-workflows.md](platform-workflows.md).

## Минимальные контрольные пары

Это библиотека выбора, не требование прогонять каждую строку на каждом проекте. Для функции используй безопасные тестовые данные; не выполняй внешнее необратимое действие ради проверки.

| Статусы, TXT-42 | «Концепт» повторён на каждом вложенном блоке | Реальные и учебные работы в одной подборке | Контекст действует на нужную область; отдельные объекты не вводят в заблуждение |
| Подсказки и drag, TXT-41/CTL-08 | «Потяните» прикрывает недоступную drag-only механику | Краткая помощь новому сложному инструменту | Механика обнаружима; применимая click/tap-альтернатива работает; нужная помощь сохранена |

| Курсор, MOT-08 | Native pointer конкурирует с управляющим follower | Штатный указатель или уместная реакция света | Ссылки, поля, выделение и фокус остаются пригодными |

| Контраст, COL-05/09 | Placeholder теряется из-за opacity на фактическом фоне | Насыщенная пара с достаточным контрастом | Проверены пары и состояния; цвет не запрещён по имени |
| Получение, PRC-06 | HTTP 200 содержит login/SPA | Registry JSON содержит нужные файлы | Статус ответа отличается от статуса материала; нет обхода внешним browser/computer use |
| Отбор, PRC-06 | Две главные ленты и знакомые эффекты приняты без теговых запросов и альтернативы | Точный образец по поручению либо актуальная основа того же продукта | Теги связаны с задачей; реальные запросы, внутреннее изучение, различие компоновки/UX и причина выбора проверены отдельно от скачивания |
| Применение, PRC-11 | Скачанный TSX лежит отдельно от действующей сборки | Адаптация сохраняет выбранную механику другим кодом | Путь, включение, версия и свойство подтверждены отдельно |
| Бриф, PRC-12/14/16 | Известен контакт, но назначены неизвестные смысл, материал и сценарий | Достаточный заданный или делегированный дизайн | Диалог закрывает существенное; нет повторного разрешения на уже заказанную механику |
| Структура, LAY-18/19/PRC-10 | Общий hero/cards/FAQ назван необычным только по цвету | Простая структура соответствует конкретному материалу | Отличие конструкции либо уместная сдержанность видны в результате |
| Слои, CTL-07/19 | Tab уходит за modal, закрытие теряет контекст | Немодальный popover не блокирует фон | Контракт роли, начальный фокус, обход, нужное закрытие и возврат, в том числе без исходного trigger |
| Undo, CTL-20 | Возвращается карточка, но данные остаются удалёнными | Один ограниченный локальный undo без универсального редактора | Отмена в заказанном объёме согласует предмет, данные и представление; многошаговая история проверяется A → B → undo → undo → redo |
| Таблица, PAG-13 | После сортировки выбран индекс и действие относится к другой записи | Уместная компактная таблица с горизонтальной прокруткой | Оба порядка на несортированных данных; selection, фильтр/страница, область безопасного bulk action |

Веб-критерии для drag и закреплённых слоёв имеют отдельные условия: [W3C Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), [Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html). Клавиатурная альтернатива не всегда закрывает pointer-требование; видимый focus не подтверждает, что он не перекрыт. Частичный тест не объявляется полным соответствием WCAG.

## Основания и границы переноса

В `grounding` различаются четыре типа: `user_policy` — согласованная редакторская политика владельца; `professional` — профессиональное или платформенное руководство; `criterion` — конкретный применимый критерий; `evidence` — ограниченное исследование или наблюдение. `context` объясняет, что именно поддерживается, а `limits` — предел вывода. Для научного источника область эксперимента не превращается в доказательство каждого вкусового запрета. Точки в заголовках и лишние правые пояснения здесь прежде всего политика редактуры по роли, а не установленный научный диагноз.

Положительный пример защищает границу конкретной записи; он не доказывает универсальную полезность решения. Если для новой ошибки уже есть канон, уточни его проверку; не создавай дублирующий ID ради объёма каталога. Структурная проверка JSON и ссылок нужна для обслуживания библиотеки, но не заменяет испытание реального артефакта. Метод и первоисточники — [sources.md](sources.md).
