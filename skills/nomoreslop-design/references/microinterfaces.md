# Обязательная проработка микроинтерфейсов

Читай при новом сайте, существенной детализации UI и работе над его меню, панелями, выбором, формами или обратной связью. Это обязательный участок реализации, а не набор необязательных украшений после hero. Для локального ремонта работай только с затронутой поверхностью; новый бриф/брендинг всего сайта не нужен.

## 1. Что должно быть реализовано

Все применимые микроинтерфейсы сайта **реализуй, адаптируй под дизайн проекта и проверь до завершения**. Пользователь не обязан отдельно перечислять dropdown, overlay, mobile menu, поповер выбора, ошибки формы и состояние ожидания. Выявляй их из навигации, содержания, действий, данных и поведения на узком экране. Запрос «сделай сайт» включает эти поверхности, когда они нужны порученному сценарию.

Кастомность означает согласованные с проектом рисунок, компоновку, плотность, типографику, цвета/темы, иконки, состояния и движение. Она не требует написать с нуля positioning, focus manager, keyboard или ARIA. Используй подходящую проверенную headless/semantic основу, доступный готовый компонент либо существующую систему проекта. Неизменённый библиотечный preset, один перекрашенный trigger, сырой browser-default popup и декоративная панель без рабочих состояний не закрывают кастомную реализацию.

Не пропускай этот участок под предлогом «это мелкие детали», «сначала красивый лендинг», «не просили явно» или «добавим после». И не создавай фиктивные опции, лишние модальные шаги и автопопапы ради выполнения списка. Применимость устанавливается настоящим действием/содержанием: прямой переход остаётся ссылкой, если дополнительный слой не помогает задаче. Для существующего утверждённого UI сохраняй его грамматику; новая проработка не означает произвольный редизайн соседних контролов.

## 2. Обязательный охват по сценариям

| Что есть в задаче | Что обязательно довести |
| --- | --- |
| Скрытые разделы навигации, меню аккаунта/действий, выбор языка/темы | Соответствующий кастомный dropdown/disclosure/action menu: trigger, открытая поверхность, активный/выбранный пункт, disabled при наличии, направление и закрытие |
| Навигация не помещается на узком экране | Кастомный mobile menu/drawer/полноэкранная панель: вся нужная навигация, доступный выход, выбранный раздел, вложенные группы по содержанию и управление прокруткой |
| Нужен временный слой: заявка, быстрый просмотр, поиск, просмотр изображения, подтверждение | Соответствующие dialog/popover/lightbox/sheet, их содержимое и рабочее действие; для модального сценария — также backdrop и блокировка фона |
| Категории, сортировка, фильтры, выбор варианта, места или параметра | Кастомный selector/segmented control/combobox/filter panel по размеру и природе данных; выбранное значение, поиск при нужном объёме, сброс/empty/disabled по сценарию |
| Действия с запросом/формой | Focus, validation, pending, success/error, повтор/исправление; inline либо toast по месту сообщения, без выдуманного успеха и бесконечного spinner |
| Информация нужна в контексте элемента, но не постоянно | Осмысленный tooltip, help popover или inline disclosure, доступный соответствующему вводу; обязательный смысл не скрывается только под hover |
| Локальные переключения содержимого | Tabs, accordion, expandable panel, toggle/switch, pagination либо другой подходящий контрол с рабочими активными/закрытыми состояниями |
| Нужны подтверждение, undo, dismiss, очистка или отмена | Видимый соответствующий путь; ошибки и закрытие не прячутся в одной иконке без доступного имени |

Не превращай таблицу в требование установить каждую семью на любой сайт. Но если такой сценарий есть, его законченный кастомный интерфейс обязателен. Например, действующая кнопка «Фильтры» не может остаться пустым кликом, скрытая мобильная навигация — отсутствовать, а форма — ограничиться красивыми полями без submit-state.

Native/system UI сохраняется, когда оно действительно нужно платформе, вводу, доступности либо явно задано: клавиатура, autofill, файловый выбор, платёжный системный flow, подходящий мобильный picker. Оформи подконтрольную сайту оболочку, сохрани значение/семантику и коротко зафиксируй конкретное основание исключения в рабочей записи. «Системные контролы привычнее» без проверки задачи не оправдывает весь набор неоформленных desktop-выборов. Кастомный вид не должен ломать системную функцию.

## 2а. Выбор управления по смыслу

В общей задаче паттерн и его место в пути принимает nomoreslop-ux по [передаче](ux-research.md); здесь — контракт реализации/визуальной интеграции и компактная основа для локального ремонта. Кастомный вид не создаёт отдельную пользовательскую модель выбора.

Выбирай паттерн до его рисунка по [общим правилам](interface-rules.md). Не делай все поля одной семьёй и не вводи универсальное число вариантов для смены контрола. Размер набора оценивай вместе с длиной/известностью значений, частотой, нуждой сравнить, доступным местом, вводом и моментом применения.

| Задача | Подходящий выбор и границы |
| --- | --- |
| Перейти или выполнить команду | Link для перехода; button для действия; menu для настоящего набора команд. Общая форма trigger не делает их одним ARIA-паттерном |
| Выбрать одно из взаимоисключающих значений | Видимые radio при пользе сравнения; segmented для компактных сопоставимых режимов; select/combobox, когда скрытый список/поиск оправдан задачей. Длинные labels не должны становиться тесной сеткой |
| Выбрать несколько независимых значений | Checkboxes, список с множественным выбором или searchable multiselect по объёму и пространству. Покажи выбранное и способ изменить весь набор |
| Включить условие | Checkbox или switch по смыслу и моменту применения: немедленно либо общей командой формы. Рисунок не должен обещать уже выполненное сохранение |
| Ввести строку или найти вариант | Различай свободный ввод, поиск по каталогу и создание нового значения. Определи commit/cancel, Enter, отсутствие совпадений и допустимые значения |
| Ввести количество, дату или диапазон | Подходящий тип/primitive с нужными единицами, границами и точностью. Slider не заменяет точный ввод, если он существенен |
| Переключить содержание или раскрыть подробность | Tabs для контекстов, disclosure/accordion для раскрытия; не подменяй ими независимый выбор значений |

У множественного выбора явно определи смысл пустого набора, «все», частичного выбора и область массовой команды: совпадения поиска, страница, каталог или вся коллекция. Область понятна до применения; фильтрация списка не меняет selection незаметно. Disabled/hidden и лимит учитываются согласованно. После сворачивания длинного набора оставь подходящий путь проверить и удалить любое выбранное значение; одно «Ещё N» не заменяет этот путь.

В составном поле различай ввод, открытие, очистку и массовое действие: их области и доступные имена соответствуют результату. Подтверждение тега не равно набору поисковой строки. Для поддержанного ввода проверь IME/composition, стрелки, Enter/Escape/Tab и смену запроса; поздний результат не подменяет текущий. Реализуй нужные группы/labels/fieldset/legend средствами выбранной платформы.

Для пресетов и зависимых полей определи изменяемые значения, видимость пользовательской настройки и судьбу несовместимого состояния. Показывай реальные условия/ошибку рядом с операцией и сохраняй правильный ввод. Не делай подтверждение каждой обратимой команды обязательным; выбирай защиту по последствиям.

Native input и проверенный semantic/headless primitive могут быть основой кастомного вида. Приведи подконтрольный рисунок и состояния к проекту, сохрани клавиатуру, autofill, ввод и значение. Не переписывай надёжную семантику и не прячь label ради внешней необычности. Системная поверхность вне контроля сайта сохраняется; локальный запрос на её оболочку не означает создание собственного OS-picker.

## 3. План и поиск до полировки

При построении композиции назови действия и возникающие поверхности. На детализации пройди их как часть очереди реализации, а не жди отдельного запроса пользователя. В существующей записи проекта достаточно компактного списка: действие/trigger → компонент и роль → подходящая основа → нужные состояния → реализация/проверка или конкретный пробел. Не создавай новый журнал, обязательную JSON-схему и отдельный документ на каждую кнопку.

Для нового нетривиального выбора используй [ресурсный подбор](resource-selection.md): реальные запросы по семейству, стилю, плотности и устройству, затем детали и альтернативы. В пуле есть компонентные источники; готовая основа должна дойти до проекта. Headless primitive даёт поведение, а не готовую визуальную идентичность. Не выбирай первый generic select и не накрывай весь UI случайными эффектами. При простом локальном исправлении используй уже принятую основу без повторного обхода каталогов.

Покажи хотя бы представительное открытое состояние повторяющейся новой семьи в черновике/детализации. Для остальных проверь различия: размеры, длинное содержимое, вложенность, края viewport и мобильный режим. Групповая реализация допустима, но один screenshot одного меню не подтверждает все диалоги/combobox и их циклы. Исследование и браузерный QA идут только через встроенный Codex IAB по [правилам экономного просмотра](browser-research.md).

## 4. Визуальный контракт

У выбранной основы обязательно согласуй:

- **Trigger и содержимое.** Размер/состояние кнопки, caret/close/check, padding/интервалы строк, ширина и высота панели, группировка настоящих пунктов, выбранный/disabled/focus/error вид. Оформление закрытого trigger без открытого popup недостаточно.
- **Связь с проектом.** Текстовые роли/вес, цветовые роли обеих реализуемых тем, границы/радиусы/тени и материал следуют его идентичности. Тёмная панель не добавляется автоматически светлому сайту; glass/blur и чрезмерное скругление не обязательны.
- **Оптический масштаб.** Надписи и иконки читаются рядом с основным UI, hit area соответствует видимой цели. Tooltip не чинит слишком маленькую кнопку. Длинная строка и реальная локаль проверяются в открытом состоянии.
- **Позиционирование и слои.** Anchor, gap, origin и направление соответствуют trigger и фактическому месту панели; на краю возможен flip/shift. Popup не обрезается overflow-предком, не уходит под sticky/header/сцену и не закрывает следующий доступный слой. Большой произвольный z-index не заменяет понятный порядок portal/backdrop/panel/nested popup.
- **Контур.** Не выбирай декоративный side/half outline автоматически: один светлый боковой штрих и обрывающиеся скругления без роли оставляют поверхность недорисованной. Проверь весь периметр и нужные состояния по CTL-21; функциональный active/focus-индикатор сохраняется.
- **Overlay.** Для модального сценария задай подконтрольный backdrop: тон/opacity и blur лишь при подходящем материале, читаемый контраст панели, отсутствие случайного двойного затемнения. Popup/dropdown не получает блокирующий полноэкранный слой без своей функции.

## 5. Поведение, движение и семантика

Выбирай паттерн по функции. Навигационные ссылки, action-menu и выбор значения — разные сущности; общий внешний вид не даёт им одинаковый `role=menu`. Для web-навигации подходит раскрытие ссылок; сложное menu-поведение не добавляется автоматически. [WAI disclosure navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/).

Для модального dialog обеспечь относящийся initial focus, удержание Tab внутри, недоступный фон, Escape/явный выход и возврат focus по логике действия. Для немодального popover не запирай всю страницу. Outside-click закрывает только там, где это уместно: не теряет введённое/несохранённое и не подтверждает опасную операцию. Вложенный popup не должен случайно закрывать родителя. [WAI Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

Combobox управляет реальным выбором/вводом, его keyboard, active option, selected value и empty-results связаны с данными. Одной анимированной listbox-панели недостаточно; длинные списки и ввод с IME не должны терять значение. [WAI Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). Поведенческие примеры APG — ориентир для семантики, не готовая визуальная система и не автоматическое подтверждение production-качества.

В каждой новой кастомной семье спроектируй вход, выход, смену selection, обратное действие и быстрый повтор. Характерная короткая анимация реализуется по motion-системе проекта; при отсутствии запрета/согласованного мгновенного режима не оставляй новую раскрывающуюся поверхность с непроработанным скачком. Анимация может быть сдержанной: контекст определяет opacity, displacement, origin, кривую, время и задержку backdrop. Не назначай scale/bounce/blur всему набору. Reduced motion сохраняет содержание и управление.

У декоративного перехода нет права задерживать logical state и новый ввод. Проверь enter → close до завершения → reopen, затем selection/submit/cancel, resize/scroll и уход со страницы. После exit не остаются невидимые pointer/Tab-цели, scroll lock или focus trap. Обычное движение не заменяет нужное управление. Motion при подключении отвечает за lifecycle/кривые/прерывание; design — за рисунок и поверхность целиком.

## 6. Приёмка и границы готовности

Перед сдачей открой каждую реализованную поверхность из настоящего trigger. Проверь актуальный широкий/узкий вид и полный относящийся цикл: вход/выход, прямое/обратное действие, отпускание, покой, повтор и возврат к секции; keyboard/touch, focus, Escape, layering/overflow и длинное содержимое. Для формы проверь наблюдаемое ожидание/ошибку/исправление; успех относится к реально выполненной операции. Серверную интеграцию вне поручения не выдумывай, её отсутствие отражай в отчёте, без служебной надписи «фейк» на самой кнопке.

Сборка, внешний вид, функция, motion и доступность имеют отдельные результаты. Все применимые микроинтерфейсы должны быть реализованы; незавершённая поверхность или непроверенное состояние остаются явным открытым участком. Нельзя назвать сайт готовым по одному закрытому экрану, списку импортированных компонентов или общему «проверил кнопки». После изменения размеров, renderer, текста либо роли повтори затронутое; неизменённые данные не собирай заново.

Кастомные микроинтерфейсы не отменяют прежние ограничения: декоративная сцена не получает пульт, «Вращать», «Разобрать» и подписи жестов автоматически; количество эффектов/попапов не является целью. Нужное управление, осмысленная помощь и реальные сценарии сохраняются.
